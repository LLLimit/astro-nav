# 从其他导航站导入网址：可行方案

可以在现有「快速导入」中增加「从导航站导入」。本次完成两级分类，以下为后续开发方案，尚未接入 AI 服务或提供抓站按钮。

## 操作流程

输入来源页面 URL → 提取实际网址卡片 → 保留来源名称、简介和分类 → AI 辅助映射到本站一级／二级分类 → 规范化 URL 并去重 → 可编辑预览 → 确认批量导入。

默认只读取输入的导航页面；可选择抓取其分类页，设置页数和网址数量上限。导航、登录、广告、页脚和页面内锚点需要排除；详情页或站内跳转链接需要进一步解析，不能把它们当成目标网址保存。每条记录保留来源页面，便于核对。AI 只整理实际抓到的数据，不生成未验证的网址；简介缺失时可沿用现有「解析网站」功能补全。

## 如何实现

- **静态 HTML 页面**：复用现有受限网络请求逻辑及 Cheerio，提取卡片结构、外链、简介和分类标题。Cheerio 不运行网页 JavaScript；内容由浏览器脚本加载的站点不能仅靠它抓取。[Cheerio 官方说明](https://cheerio.js.org/docs/intro/)
- **动态页面**：必要时用 Playwright 的浏览器加载页面并取得渲染后的 HTML，再交给同一提取流程。浏览器部署需要额外内存，宜作为按需任务或独立工作进程。[Playwright Page API](https://playwright.dev/docs/api/class-page#page-content)
- **分类整理**：将提取结果与本站分类树发送到可配置的 AI API，要求返回固定 JSON 结构。服务端验证 URL 与分类 ID，只接受实际提取的网址；未能匹配的条目标为「待选择分类」。新分类先在预览中提出，确认后再创建。
- **导入与去重**：复用现有 URL 规范化、哈希唯一约束和导入 API，每批最多 100 条，较多内容分批处理。显示新增、重复、失败数量及失败原因。

提取规则能覆盖常见导航卡片，但不同站点的结构、跳转和访问限制不同；针对经常使用的来源做适配器会更稳定。不能保证任意导航站都能一次完整导入。

## 资源与配置

抓取、AI 请求和导入时会占用服务器资源，属于按需操作，不持续后台运行。静态 HTML 的开销较小；动态浏览器开销明显更高。AI API 有独立调用费用，需要配置提供商、模型、API 地址与密钥，密钥只保存在服务器。

建议先为一个具体来源实现 HTML 提取、预览和去重，再接入可选 AI 分类。对于已经能提取到分类标题的站点，不调用 AI 也能批量导入。
